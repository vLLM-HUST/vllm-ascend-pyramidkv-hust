# PyramidKV 0.4.0rc1

This is the first published standalone release candidate. It targets the pinned
Qwen3.5-35B-A3B text/BF16/TP2 Ascend profile in the [support matrix](../support-matrix.md).
It owns its scheduler, worker, transaction and attention metadata adapter and
requires no KVCompress installation, import or runtime. Activation is default-off.

## Release choice and scope

A candidate release makes the existing functional qualification reproducible from
public artifacts while full current-version effect evaluation is still pending.
A source-only checkpoint would not close artifact delivery; a general stable or
performance recommendation would exceed the available qualification. The selected
rc1 label is an implementation decision under the user's publication instruction.

The algorithm and supported runtime behavior are unchanged from the reviewed
`44acef5` implementation. Release changes set the version and explain delivery.
Historical shared-adapter quality, 8 GiB negative results and bounded 2 GiB gains
remain historical evidence, not measurements of this candidate.

## Download and install

The public distribution channel is the [GitHub prerelease](https://github.com/vLLM-HUST/vllm-ascend-pyramidkv-hust/releases/tag/v0.4.0rc1).
The release contains the wheel, sdist, `release-provenance.json` and `SHA256SUMS`.
The provenance binds the exact source commit/tree and artifact hashes. Download
all four assets into one directory, then:

```bash
sha256sum -c SHA256SUMS
python -m pip install --no-deps ./vllm_ascend_pyramidkv_hust-0.4.0rc1-py3-none-any.whl
# The sdist supplies configuration, launch scripts, docs and validation commands.
tar -xzf vllm_ascend_pyramidkv_hust-0.4.0rc1.tar.gz
cd vllm_ascend_pyramidkv_hust-0.4.0rc1
```

Use a prepared, matched host environment; the wheel intentionally does not replace
hardware-specific dependencies. Follow [direct launch and rollback](../install-and-rollback.md)
with the aligned configuration. A vLLM/Ascend version range alone is not a serving
qualification. There is no PyPI publication claim for this candidate.

## Migration

Current standalone activation and JSON `schema_version: 1` remain supported.
The retired schema-v1 host-provider API (`get_provider`, `PyramidKVContractProposal`,
`provider`, `registry`, root `contracts`, `legacy_contracts`) is removed. Algorithm
consumers import `PyramidKVConfig`, `PyramidKVSelection` and selection/materialization
functions from `vllm_ascend_pyramidkv.algorithm`.

Users of the shared adapter must stop the old process, remove its activation,
install this package and use `ascend_pyramidkv` plus `VLLM_ASCEND_PYRAMIDKV_*`.
The full migration procedure and fresh-process rollback are in the installation
manual. Existing processes cannot be unpatched by uninstalling the wheel.

## Acceptance and further qualification

Release acceptance covers package identity, independent disabled discovery,
optional Manager lifecycle, pinned-host tests/NPU oracles, installed-wheel TP2
requests with native and batched metadata, APC/MTP and fresh-process disabling.
The release notes link the actual acceptance record; planned checks alone do not
establish success.

[Issue #1](https://github.com/vLLM-HUST/vllm-ascend-pyramidkv-hust/issues/1)
tracks current-version quality, net service cost and actual request capacity.
[Issue #8](https://github.com/vLLM-HUST/vllm-ascend-pyramidkv-hust/issues/8)
tracks the five-dataset execution/judge requirements. No throughput, HBM saving,
maximum-concurrency or broad quality claim is introduced by this release.
