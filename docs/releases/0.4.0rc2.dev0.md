# PyramidKV 0.4.0rc2.dev0

The November 6, 2026 candidate-delivery stage of [issue #1](https://github.com/vLLM-HUST/vllm-ascend-pyramidkv-hust/issues/1)
is complete: the Qwen3.5 replay-boundary fix was reviewed and merged, remote CI
passed, original evidence was archived, and the public candidate was downloaded
and installed successfully. This remains a development prerelease. The parent
long-context challenge and the task-quality program remain open.

## Exact artifact and installation

Download the four assets from the [GitHub prerelease](https://github.com/vLLM-HUST/vllm-ascend-pyramidkv-hust/releases/tag/v0.4.0rc2.dev0):
the wheel, sdist, `release-provenance.json` and `SHA256SUMS`. The release tag points
to `3db81efc6a3ff9c7e1a5f63d9b890e20e4f687c6` ([PR #37](https://github.com/vLLM-HUST/vllm-ascend-pyramidkv-hust/pull/37)).
Its tree equals the reviewed and serving-tested tree
`05313664b8cc37553eecb6f6aa0140bdcf93aceb`.

| `vllm_ascend_pyramidkv_hust-0.4.0rc2.dev0-py3-none-any.whl` | `5392b2a8afa971cf0af1b9928d693ab80a71976256de87e7f85b5f9c3a4819be` |
| `vllm_ascend_pyramidkv_hust-0.4.0rc2.dev0.tar.gz` | `0463ea98ffbc2082615f4db357956185dd95c9c6710d5b3a5935e4eedf2bc931` |

After downloading all four files into a new directory:

```bash
sha256sum -c SHA256SUMS
python -m pip install --no-deps ./vllm_ascend_pyramidkv_hust-0.4.0rc2.dev0-py3-none-any.whl
tar -xzf vllm_ascend_pyramidkv_hust-0.4.0rc2.dev0.tar.gz
cd vllm_ascend_pyramidkv_hust-0.4.0rc2.dev0
python scripts/check_standalone_install.py
```

Serving requires the prepared host in [installation and rollback](../install-and-rollback.md)
and the exact [support matrix](../support-matrix.md). Use the extracted source
for launchers and configurations. The shared TP2 eager launcher defaults to C32
and an automatic pool, so it is not the frozen C128/558-block acceptance launch.
That launch, original request bank and complete logs are in the evidence below.
Disable compression and restart in a fresh process to roll back; changing an
environment variable cannot remove patches from a running process.

Earlier experiments also used the development version string `0.4.0rc2.dev0`
with different wheel bytes. Identify this public artifact by tag commit and
SHA256, not the version string alone. Do not replace existing release assets
with a build from a later documentation or source revision.
