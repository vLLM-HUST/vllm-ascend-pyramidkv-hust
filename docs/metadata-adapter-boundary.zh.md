# 下游元数据适配器的归属

[English](metadata-adapter-boundary.md) | 简体中文

[共享仓库维护者的要求](https://github.com/vLLM-HUST/vllm-ascend-kvcompress-hust/pull/33#issuecomment-6460186520)
明确了方向：上游提供可覆盖的通用接口，PyramidKV 在下游维护专用元数据实现和状态。
接口边界明确前，共享 PR #33 保持 Draft；其中现有运行时代码是实验参考，尚不是符合新边界、可合并的实现。

## 应迁回下游的代码

本次提出的 `_metadata_tensor_cache`、`_batched_slot_storage`、修正张量缓存策略、
逐层槽位批量计算和候选开关应归 PyramidKV 适配器所有。稳定槽位视图及每次调用独立的长度视图
也由适配器持有。方法专用的 MTP 长度／槽位修正应通过通用元数据接口完成，避免再增加共享派发分支。
调度器分配、事务确认及原生生命周期仍归共享层负责。

此次范围是 PR #33 新增的优化。已合并的查询观察、逐层状态及图执行集成，在上游重构提供替代契约前
仍属于当前宿主契约。本文没有删除这些既有行为，也没有把旧依赖描述成已消除。

## 提交给上游设计的接口需求

当前 `KVCompressionMethod` 提供缓存绑定、压缩和查询观察接口，没有可覆盖的元数据构造回调；
插件直接实例化共享 provider。仅靠缓存绑定无法让下游替换逐层注意力元数据和 MTP common 视图，
因此现有公开方法契约还不足以完成迁移。

以下是待讨论需求，不是假定已经存在的公共 API：

| 边界 | 所需契约 |
| --- | --- |
| 图捕获前绑定 | 已验证的层身份、缓存几何及 token 上限；由下游持有地址稳定的存储 |
| 每次元数据构造 | 只读的已提交物理锚点、当前请求顺序、位置、展开块表及原生元数据视图 |
| 返回视图 | 按层组织的注意力元数据和对应的推测 common 视图，覆盖拒绝草稿处理 |
| 生命周期 | 明确流与对象有效期、槽位补齐、请求移除、取消、抢占、重启及缓存重新绑定 |
| 兼容及回退 | 显式能力／版本校验；下游不支持该布局时可调用的原生继续路径 |

最终名称、签名及派发模型由上游维护者确定。不要通过 monkey-patch provider、替换实例的类、
新增对 provider 私有字段的导入，或注册竞争的宿主 hook 来完成迁移；这些做法仍保留了本次要消除的依赖。

## 迁移验收

通用契约可用后，在本仓库实现适配器和状态，只使用约定边界；保留不支持布局的原生路径，
完成验证前继续显式开启。覆盖请求重排与混合批次、CPU/NPU 元数据位置、展开页、补齐、
旧长度视图不可变、图槽位地址稳定、MTP 回滚及各类重置／抢占生命周期。
先验证原生槽位等价和真实图执行／推测服务，再形成新的性能结论。

[冻结候选与证据](runtime-performance-boundary.md)继续绑定原实测源码。迁移文档或定义接口不会把旧回执
转移给新代码。本次归属调整不包含新的硬件实验；后续代码迁移需要独立验证。
